# ADR-0002: Distribution — self-contained skill package (option A)

Date: 2026-11-06
Status: ACCEPTED (maintainer review pending; reversible before v1.0)

## Context

`gh skill install` and `npx skills add` copy only the skill directory into the user's host path. A `SKILL.md` that points to `../../scripts/` of the source repository breaks after installation. Copilot Cloud Agent has no access to the developer's global installs. Installers must not run unreviewed remote code or `pip install`.

## Decision

Ship the deterministic core **inside** the skill directory:

```text
skills/agent-handoff-manager/
  SKILL.md                 # canonical, frontmatter name == directory name
  scripts/handoff.py       # stdlib-only, Python 3.10+, single file
```

`SKILL.md` invokes it with a path relative to the skill directory (the host resolves the base directory) and states the Python 3.10+ prerequisite. There is no build step, no wheel, no network access at install or run time.

## Alternatives

- B) pinned wheel/`pipx`: second install step, requires a registry or release asset, cannot work in Cloud Agent without extra setup. Rejected for v1.0; may be added later as an optional channel.
- Copy `scripts/` to repo root and reference by URL: breaks offline and pin guarantees. Rejected.

## Consequences

- The core must stay single-file/stdlib until the package is split; tests import from the skill path.
- Release artifact = the skill directory + checksum. Version in `handoff.py` `VERSION` must match the release tag.
- A host that does not run Python (or has Python < 3.10) cannot use the core; `doctor`/SKILL.md must say so rather than fail silently.
- Verification of the claim "SKILL.md alone is enough" is the clean-copy test in `tests/test_distribution.py`.
