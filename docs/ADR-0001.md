# ADR-0001: Separate durable state from session lifecycle

Date: 2026-11-06  
Status: PROPOSED (approval needed in project implementation)

## Context

Upstream ④ stores canonical project handoff state under `AGENT_HANDOFF.md` and `.agent-handoff/`; upstream ③ stores independent session handoffs under `.handoffs/` and a central cross-project index.

## Decision

- Persist long-term facts and validation only in project canonical state.
- Store session snapshots separately in per-session folders, with content and metadata.
- Build search indexes from session records; avoid mutable centralized authoritative INDEX.
- Read-only initial resume (verification), reversible archive and explicit evidence-based completion.
- Track upstream SHAs but require an integration PR before adoption.

## Alternatives considered

1. Copy both upstreams unchanged: fast, but overlapping records, competing commands and Claude-only management remain.
2. Fork and merge both repositories on every upstream change: very high maintenance and automated merge risk.
3. **Thin adapters + shared core** (selected): more initial work, but stable public API and cautious upstream adoption.

## Consequences

- Some upstream new features need adapter work rather than appearing instantly.
- Compatibility tests and schema migrations become mandatory for major changes.
- Multi-agent concurrency needs additional policy; this ADR does not pretend to solve distributed locking.
