# ADR-0006: Per-execution snapshots and immutable results

Date: 2026-11-15
Status: ACCEPTED for implementation by owner ("커밋하고 개발 진행해")

## Decision

Preserve session schema v1 and `open/archived` storage state. Add independently versioned execution records under `.handoffs/runs/<run-id>/`: immutable `run.json` and optional immutable `result.json`. Capture a validated session snapshot, revision and payload hash when starting a run under the existing store lock. The run stays in place when its source session is updated, archived or restored.

Commands: `run-start SESSION_ID --task TEXT --agent NAME --agent-instance TEXT --request-id KEY [--supersedes RUN_ID]`, `run-finish RUN_ID --payload FILE --request-id KEY`, and `list-runs [--session SESSION_ID] [--all-worktrees]`. `resume` includes related runs and diagnostics; `doctor` validates runs, source references, snapshot hashes, pending files and result references. Old stores need no migration; reading must not create a runs directory.

Start request keys are unique within the local store. Replaying the same key and arguments returns the original run, including its original snapshot even if the session changed. Changed arguments with the same key fail. Finish keys are scoped to their run: same key and same payload returns the original result; any other attempt to replace a submitted result fails. A correction/retry creates a new run referring to the superseded run, with the same session and task. Superseding does not delete or automatically select a result.

Each run records a distinct agent instance and task. Result outcomes are `completed`, `partial`, `blocked`, `failed`; absence of a result means `in_progress`, not success. Results contain a summary, validation claims, changed files, result commits, remaining work, and optionally `selected_runs`. Selected runs must be distinct, submitted executions for the same session, never the run itself. They record a coordinator's explicit selection, not verified approval. Fresh Git observations are captured at start/finish. Integration is an ordinary run naming the selected results and recording tests against the integrated HEAD. Official truth remains in `AGENT_HANDOFF.md` and `.agent-handoff/` under the existing evidence/approval rules.

## Concurrency and publication

Reuse `StoreLock` only during validation, snapshot capture, lookup and atomic publication. Never hold it while an agent works or tests. Unique run IDs separate writers. Existing session CAS remains mandatory; do not retry a revision conflict by merely substituting the latest revision. Source update/archive and start serialize through the same local lock. Start accepts archived sources too; a moved source is not lost. Finish depends on the captured snapshot, not a mutable session file, so archive/updates do not block submission.

`run.json` publishes before `result.json`; no result is valid without its run. Interrupted creation is diagnosed, never promoted. Replaying a start/finish after publication returns the published record without rewriting. Pending/empty directories and stale locks require inspection; no automatic deletion. All run inputs, results and persisted snapshots are validated for credentials and safe paths; no commands in records execute.

Worktrees have independent stores and locks. Read-only `--all-worktrees` exposes origins; conflicting copies with the same run ID, request key, or final result are errors rather than last-writer-wins. Git/PR integration remains required across worktrees/machines. No global authoritative index, distributed work-claim guarantee, scheduler, or automatic merge.

## Alternatives

- Append every result to session.json: less scaffolding but shared edits, revision conflicts and lost original inputs.
- Central database/service: stronger distributed coordination, but changes the product's installation and operating model.

## Acceptance

Tests must cover old sessions, lifecycle, source updates/archive, idempotent retries/conflicts, parallel starts and finishes, finish/archive races, crash/pending states, invalid/symlinked/secret records, isolated skill-copy execution, non-ASCII paths, dirty Git and multiple worktrees. Run the full suite on Windows and Linux; document any platform or host limits without claiming untested support.
