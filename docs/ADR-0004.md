# ADR-0004: `write` takes an explicit JSON payload file from the host

Date: 2026-11-07
Status: ACCEPTED

## Context

The Python core cannot read a model's conversation, and must not claim to. Hosts differ (Claude Code, Codex, OpenCode, Antigravity, Copilot); some have no slash commands. Handoff content is model-generated and therefore unverified.

## Decision

- `write --payload <file>`: the host agent composes a JSON object (schema: `docs/SCHEMA_SPEC.md`) from facts it observed and passes it as a regular, non-symlink file <= 256 KB. Unknown fields are rejected.
- The core adds only what it can observe itself: id, timestamps, revision, git observation (`.handoffs/` excluded from dirty), `depth`.
- Everything in the payload is stored as `claims_are_unverified: true`. `validation.result=passed` and `completed` never become official state; `write` only prints `state_change_candidates` as proposals.
- No stdin/inline-JSON mode and no transcript scraping in v1: a file keeps secrets out of shell history and process lists and works identically in PowerShell and Bash.

## Alternatives rejected

- Core extracts the conversation: impossible across hosts and would invite false claims.
- Inline JSON on the command line: quoting differs across shells (observed breakage on Windows) and leaks into process listings.

## Consequences

- Quality of a handoff depends on the host agent; `--depth` enforces completeness only, not truth. `resume` independently re-observes git and file existence.
- Hosts must delete the temp payload file themselves (SKILL.md instructs this).
